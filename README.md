# papder-deepread
# paper-deep-dive · 论文深度解读 Skill

一个给Agent用的 skill：把一篇论文拆成**两段式解读**。先讲清“论文说了什么”，再用第一性原理回答“为什么这么做、创新在哪、哪里站不住、这个 idea 是怎么想出来的”。

默认读者是**有基础机器学习常识的本科生**：深度不打折，但每个术语都会解释，公式都会逐符号说明。

---

## 它能产出什么

| 部分 | 回答的问题 | 包含内容 |
|---|---|---|
| 开头 | 读这篇要先懂哪些词？ | 「术语速查」表，8~15 个核心术语 |
| 第一部分：五问 | 论文说了什么（只陈述，不评判） | 1. 背景　2. 方法　3. 实验设计　4. 实验结果　5. 结论与展望 |
| 第二部分：第一性原理 | 为什么、行不行、怎么想到的 | 1. Task（形式化）　2. Challenge（结构性挑战）　3. Insight & Novelty　4. Potential flaw　5. Motivation（问句推演链） |

几个和普通“论文总结”不一样的地方：

- **区分新旧**：明确哪些是这篇文章真正新的，哪些沿用前作。没有方法创新就直说，并指出真正贡献在哪（例如实验设计或度量协议）。
- **看失败案例**：把表现差的任务放在一起找共同结构，作为 Potential flaw 的素材。
- **分清测量和解释**：作者的结论里，哪些是数据直接测出来的，哪些是作者的解读，会分开标。
- **Novelty 固定格式**：【解决什么问题】->【受哪个 insight 启发】->【具体设计了什么，拆掉它会失去什么】。
- **Potential flaw 可以直接拿来选题**：按“问题真实性 / 可形式化程度 / 可验证性 / 工作量”打分，首选方向附实验设计草案，优先考虑不需要大算力的方案。
- **Motivation 做事后追认核对**：用问句还原当时研究者的推理链，再逐步检查每一步依赖什么，指出哪一步是真正稀缺的。
- **数字不凭印象**：所有 benchmark 分数都要来自实际读到的段落。

## 安装

1. 下载本文件夹（包含 `SKILL.md` 和 `README.md`），打包成 zip。(或者直接提供链接给Agent自行执行）
2. 打开 **Settings → Capabilities → Skills**（不同版本入口名称可能略有差异），选择上传 skill，上传这个 zip。
3. 确认 skill 已启用。
   

### 其他支持 system prompt 的工具

把 `SKILL.md` 中 `---` 分隔的头部之后的正文，整段作为 system prompt 或对话开头的指令使用即可。

---

## 使用方法

安装后，这样说就会触发：

```
深度解读一下这篇论文 [附上 PDF]
精读 arXiv 2005.14165
分析这篇论文：Attention Is All You Need
（附录里有一个现场的文档可以查看效果）
```

也可以直接指定：`/paper-deep-dive` + 论文 PDF / 链接 / 标题。

**输入建议**

- **最好直接给 PDF**，分析最完整。
- 只给标题或 arXiv 编号时，Claude 会先检索原文再读（需要开启联网搜索）。
- 如果拿不到全文，输出会说明是基于哪些部分分析的。

**输出形式**

- 默认直接在对话里用 markdown 回复，不额外生成文件；写完会问你要不要整理成文档。
- 公式全部用纯文本（如 `argmin_theta E_{x~D}[L(f(x), y)]`），不用 LaTeX，方便复制到任何地方。
- 输出很长，一篇论文通常要几千到上万字，建议用能力较强的模型。

## 自定义

直接编辑 `SKILL.md` 就行，常改的几处：

| 想改什么 | 改 `SKILL.md` 里的哪一节 |
|---|---|
| 读者水平（比如改成研究员，去掉基础解释） | 「读者设定」「可读性要求」 |
| 输出语言 | 在「输出要求」里加一句，例如“全文用英文输出” |
| 想要直接生成文件 | 「输出要求」最后一条 |
| 增删分析维度 | 「第一部分」「第二部分」的各小节 |
| 质量自检清单 | 末尾「常见失败模式」 |

## 注意

- 这是一个**阅读辅助**工具。Potential flaw 和 Motivation 是基于论文内容的推演，不是定论，引用前请对照原文核实。
- Future work 部分可能会提到“某方向后来成了重要工作”，这是后见之明，会明确标注，不算作论文本身的贡献。
